# 完整备份格式 v1

备份后缀为 `.dgbk`，系统文件选择器读写，不需要广泛存储权限。密码为空导出普通 ZIP；填写密码并在界面确认后导出加密信封。普通备份包含账号密码等敏感资料，文件由用户自行保管。

## 普通归档

按顺序写入 `manifest.json`、`data.json`、`attachments/<文件名>`。清单包含格式标识 `daigan-backup`、格式版本 1、来源数据库 schema 版本、导出时间、生成器、每表数量、data.json 的 SHA-256、附件编号/名称/MIME/大小/SHA-256 和附件总大小。data.json 是 `daigan-backup-data` v1，含完整表清单、每表明确列顺序和具有 JSON 字符串/整数/NULL 类型的行。

包含 18 个持久业务表：老板及编号计数器、游戏账号（含登录凭据）、模板/分类/任务/种子状态、批量完成及撤销明细、订单/托管期次/任务定义/发生记录、截图引用、收款/更正历史/建单幂等记录、提醒设置。订单和托管期次中的模板与游戏日历快照原样保留。

`app_settings` 是本机身份及恢复提交标记，恢复时产生新身份；`reminder_deliveries` 是可重建的本机通知去重状态，恢复时清空。两表明确列入本地专用目录，不导出。提醒开关和时间与业务数据处于同一 Room 事务中恢复。

v1 要求清单 schema 与当前应用 schema 完全一致（目前为 7）；不同 schema、未知格式或信封版本在替换前拒绝。数据库升级仍由既有迁移链处理，不能把任意历史逻辑备份假装为当前结构。

## 可选加密信封

大端布局：8 字节 ASCII `DAIGANBK`；版本 u8=1；KDF u8=1；迭代次数 i32=210000；盐长度 u8=16；随机盐；nonce 长度 u8=12；随机 nonce；整个 ZIP 的 AES-256-GCM 密文及 128 位认证标签。KDF 使用平台 `PBKDF2WithHmacSHA256`，每次重新生成盐和 nonce。解析时先限制版本/KDF/迭代次数/盐和 nonce 长度，再派生密钥；密码最多 256 字符。密码数组和派生字节在使用后擦除；不记录秘密日志。解密归档仅暂存在应用私有恢复目录，认证成功后才解包，完成/失败后删除。

## 输入和资源边界

归档最多 512 MiB；清单 1 MiB；数据 JSON 64 MiB；条目 5000；附件 2000；单图 32 MiB；附件总计 384 MiB。声明和实际字节均检查。超过 8 MiB 的解压内容还限制压缩比为 200。导出同样拒绝无法由本版本读回的大小/压缩比。

禁止绝对路径、目录、路径穿越、分隔符嵌入、未知条目、重复条目、未登记或缺少的附件。附件清单与数据行的路径、编号、MIME、大小须相符，全部校验和必须匹配。JSON 深度、精确表/列集合和值类型均限制；隔离的真实 Room 数据库再验证结构、枚举、外键、业务归属、有效收款上限和 SQLite 完整性。预览和明确确认之后才进行替换。

SHA-256 用于发现损坏，普通归档的校验和不提供对抗主动修改的认证；需要密码保护时使用 GCM 信封。
