# 架构底座与数据稳定性补充决策

本文件修订 android-v1 开发计划中的初始化、依赖注入、数据访问及升级策略，优先于原计划相应描述。用户要求尽量基于成熟开源架构改造；现有页面和业务需求不变。

## 开源底座

采用 https://github.com/android/architecture-templates 的 `base` 分支作为源代码起点。其 README 明确用于新项目，包含单模块、Compose Material 3、Navigation、ViewModel、Room、Hilt、Coroutines/Flow、单元及 UI 测试。保留相应分层、构建与测试骨架，替换示例字符串业务，不重新自创框架。

执行任务 1 时先固定上游 commit SHA，记录至 docs/upstream-foundation.md，保存许可证、版权声明和修改说明；先跑未改业务的基线构建/测试，再逐步改包名、页面和模型。依赖以该 commit 的兼容组合起步，必要的工具链升级单独验证，不混用不同项目版本目录。

本次读取 base 的 app/build.gradle.kts 发现当前上游 compileSdk/targetSdk 为 37、导航为 Navigation 3，本机仅发现 SDK 36.1。因此执行时优先选择兼容已安装稳定工具链的上游历史提交并记录 SHA；不能仅为追随分支最新状态直接升级工具链，不能把未构建的最新版称作可用底座。导航沿用所选提交的整套实现，不混搭不同代际示例。

其他参考：
- https://github.com/android/architecture-samples ：借鉴任务 Repository、ViewModel、Flow 与测试。不是直接产品模板；其远程示例和清空重载路径不引入本项目。
- https://github.com/android/nowinandroid ：借鉴本地事实来源、Repository 边界、DataStore 偏好与依赖注入测试；不引入新闻业务、服务端同步和完整多模块结构。

上述官方项目是工程基础与参考，不能代表我们的续期、账务与恢复逻辑已被验证。

## 数据访问与存储

数据流为 Compose → ViewModel → 业务操作/Repository → Room DAO → SQLite；读取通过 Flow 反向更新。使用 Hilt 注入数据库、Repository、时间源与调度器。ViewModel 不直接访问 DAO 或写文件。

业务资料统一进入 Room/SQLite，作为唯一事实来源。收款总额、欠款和统计从订单期次及流水计算，不在多个页面各存一份余额。金额用整数分；任务周期归属使用显式游戏时区与刷新规则。

DataStore 仅保存显示偏好等不需和业务跨存储事务的设置。决定提醒行为的配置存 Room，避免恢复过程中两个存储版本不同。截图放应用私有文件区，数据库引用稳定附件 ID，不将图片 Base64 塞进数据库。

## 关键写入的一致性

- 建单和首笔收款、续期和任务配置、批量完成及撤销、收款及归属都在数据库事务中完成。
- 用外键、唯一索引及操作 ID 防止串账号、重复期次、重复打卡、重复收款。核心事务不以后台无等待写入后直接显示成功。
- 删除老板、账号或订单不能级联抹掉账款和打卡。第一版以归档为主，外键禁止误删引用记录；更正款项保留变更痕迹。
- 附件先落地再提交引用；失败清理临时文件。删除附件先变更引用，延后清理无引用文件。

## 升级与恢复

Room 必须启用 exportSchema 并提交 schemas；禁止 fallbackToDestructiveMigration。每次表变更提供迁移路径，用 MigrationTestHelper 验证历史版本升级并核对关键数据，不把“数据库能打开”作为唯一通过条件。

备份导出业务快照与附件清单，不直接复制仍打开的 SQLite 主文件，避免漏掉 WAL 中的数据。备份包含格式版本、数据库版本和附件校验。

恢复先在临时区校验，展示摘要并经用户确认；暂停业务写入，使用可恢复的切换记录管理数据库与附件替换。切换前保留原完整快照，启动时检查未完成恢复并完成或回滚。数据库事务不能假装能同时回滚文件系统。

普通备份和可选密码加密不变。恢复测试额外覆盖应用在验证、数据库替换、附件切换各阶段被终止，重新启动后原资料或完整新资料必须可用，不能混合。

## 计划调整与验收

任务 1：改为从官方 base 固定 commit 导入，保留 Hilt 与上游测试；增加 Schema 导出、首次 v1→v2 迁移演练、真实数据库约束测试。

任务 2—6：所有 Service 经 Repository/事务边界访问数据库，增加归档、重复提交及跨页面一致性测试。UI 测试可用 fake，数据测试必须用真实 Room，不能只测内存假实现。

任务 7：加入数据库与附件跨资源恢复状态机及中断恢复测试。

任务 8：持续集成执行单元测试、Lint、APK 构建；设备验证执行 Room、迁移与 UI 测试。先验证离线、进程终止、升级保留资料、备份恢复，再宣布首版数据稳定性达到验收要求。
