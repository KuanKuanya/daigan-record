# 游戏代肝管理 Android V1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox syntax for tracking.

**Goal:** 交付离线可安装 APK，完成老板账号、接单、任务打卡、续期、收款、模板、提醒与备份全流程。

**Architecture:** 单 Android 应用模块，按功能划分页面和业务服务；Room 是事实来源，Compose 使用 ViewModel 与 Flow 驱动。时间规则、金额、续期、备份独立于界面，方便验证。

**Tech Stack:** Kotlin、Compose Material 3、Room、Coroutines/Flow、Navigation Compose、WorkManager、JUnit、Android instrumentation。依赖版本在项目初始化时按本地 Android Studio 兼容组合核实并锁定于版本目录，不浮动升级。

## Global Constraints

- 本地单机，无注册、服务器和应用身份验证；交付 APK。
- 顶部设置独立页面；三个主板块名称为今日事项、账号信息、数据统计。
- 老板列表只提供“新增”；订单必须从老板下的游戏账号添加。
- 收款途径只有微信、支付宝、其他；续期不新增订单。
- 模板更新不改已有订单；普通和加密备份均支持。
- Android 最低版本默认 API 26；应用工作名“代肝记录”，包名 `com.daigan.record`，中文优先，支持系统深浅主题。

## 环境与工作方式

当前项目仅有设计文档，没有 Git 仓库。已发现 Android Studio、JDK 21、Android SDK 36.1 与构建工具 36.1.0；未确认依赖下载和实际构建。执行时初始化 Git，先完成工具链验证，不凭原型宣称 APK 已完成。

当前沙箱不允许 ADB 监听端口，设备检查失败。单元测试与构建先行，设备验证需在允许 ADB 的环境执行；如受阻必须报告未验证项。

推荐在当前会话按阶段顺序实现，阶段结束保存提交，核心流程可用后优先交付测试 APK，再加入其余能力。不以演示数据代替持久化。

## Review Focus

1. 刷新边界、时区和跨月：同一瞬间任务归属稳定，金额按实际收款归月（任务 3、5）。
2. 连点完成或收款：不重复生成记录；撤销不改原先完成项（任务 3、5）。
3. 续期前后同一天：旧记录保留，新期不重复产生任务（任务 4）。
4. 备份损坏或密码错误：不能破坏当前数据库或附件（任务 7）。
5. 长昵称、空列表、大字体及拒绝通知许可：主要流程仍能使用（任务 2、8）。

## 文件与接口边界

主代码位于 `app/src/main/java/com/daigan/record/`。`core/` 放金额和游戏日规则；`data/` 放 Room 表、DAO、数据库、附件存储；`feature/` 下按 today、accounts、orders、stats、templates、settings 分目录，每个页面的 UI、ViewModel 与业务服务分文件；`backup/` 和 `notifications/` 单独承担文件交换与通知。

约定：实体 ID 为 UUID 字符串，日期使用 LocalDate，事件时刻使用 Instant，时区使用 ZoneId，金额以 Long 分存储，显示时格式化；数据库持久化类型通过转换器处理。变更操作是 suspend 函数，读取列表为 Flow。测试目录镜像业务包。

## Task 2：老板与账号管理

**Files:** `feature/accounts/AccountsScreen.kt`、`OwnerDetailScreen.kt`、相应 ViewModel、`AccountService.kt`；测试 `AccountServiceTest.kt`、账号页面测试。

**Interfaces:** `createOwner(nickname: String): Owner`、`createAccount(ownerId: String, input: AccountInput): GameAccount`；`observeOwners(): Flow<List<OwnerSummary>>`。老板固定编号从事务内序号生成；AccountInput 包含模板、区服、UID、登录方式及凭据。

- [ ] 先测试编号并发唯一、昵称修改不变编号、多账号隔离、验证码方式不留旧密码、空列表和超长昵称；运行确认失败。
- [ ] 实现已确认的列表、详情和表单，新增订单仅从账号发起；显示和复制凭据不要求验证。密码和凭据不得写入日志。
- [ ] 验证中文长文本、大字体和返回路径，新增记录重启仍在；运行相关测试并提交。

## Task 3：短期单、托管打卡与游戏日期

**Files:** `core/GameCalendar.kt`、`feature/orders/CreateOrderScreen.kt`、`OrderService.kt`、`feature/today/TodayScreen.kt`、`CheckInService.kt`；测试同名服务及日历测试。

**Interfaces:** `gameDate(at: Instant, rules: RefreshRules): LocalDate`；`createOrder(accountId: String, draft: OrderDraft): Order`；`complete(occurrenceIds: Set<String>): CompletionBatch`；`undo(batchId: String)`；`recordHistorical(taskId: String, gameDate: LocalDate, completed: Boolean)`。发生记录以任务、所属期次、周期键唯一，完成批次仅记录本次改变的项。

- [ ] 先测试刷新前后一秒、时区、周界、每 N 天以开始日为锚、指定星期、到期不生成；重复点击幂等，撤销保留先前完成，历史补录保留录入时刻。
- [ ] 实现订单快照、数值进度、任务周期、本地查询和原型中的两页布局。短期支持可空截止时间；托管日期含首尾日。勾选与批量完成在事务中更新。
- [ ] 实现任务附件选择和持久化复制，图片归具体发生记录，支持替换删除；文件失败不能留下成功的附件记录。
- [ ] 运行服务测试与页面关键路径，确认短期排序、折叠完成项、进度恢复和任务截图重启后可读，提交。此时产出第一份核心流程测试 APK。

## Task 4：详情、续期与历史

**Files:** `feature/orders/OrderDetailScreen.kt`、`RenewalService.kt`、`CheckInHistoryScreen.kt`；测试 `RenewalServiceTest.kt`。

**Interfaces:** `renew(orderId: String, days: Int, priceCents: Long, at: Instant): HostingPeriod`；用订单时区取得续期当天，结束日为起始日加 days-1；允许直接编辑结束日并同步天数。

- [ ] 先测试到期续期保留订单 ID、期次增加、价格独立、实收为零、旧打卡和欠款保留；重复提交只产生一期；续期日任务不会跨期混合。
- [ ] 实现详情三个页签、历史日历及补录、截图查看；到期单续期，沿用任务配置并建新期。第一版已生效期不提前重叠续期。
- [ ] 运行测试，验证 30 天托管、隔日续期、跨月、上期欠款均正确，提交。

## Task 7：备份恢复

**Files:** `backup/BackupService.kt`、`BackupCodec.kt`、`BackupCrypto.kt`、`feature/settings/BackupScreen.kt`；测试 `BackupRoundTripTest.kt`、`BackupFailureTest.kt`。

**Interfaces:** `exportBackup(password: CharArray?): BackupArtifact`、`inspectBackup(input: InputStream, password: CharArray?): BackupPreview`、`restoreBackup(preview: BackupPreview)`。空密码为普通 ZIP；可选加密采用标准 AES-GCM、随机 salt/nonce 与带参数版本的 PBKDF2-HMAC-SHA256。不自创密码算法。

- [ ] 先测试普通/加密全量往返、中文资料与截图、错密码、损坏清单、缺附件、不支持版本、路径穿越及解压超限均拒绝，现有数据不变。
- [ ] 一致性快照导出，文件头包含格式版本和附件校验；临时区校验并展示恢复摘要，确认后整库替换，失败回滚。备份密钥不写入设置或日志。
- [ ] 系统文件选择保存/读取，密码选填，有密码时二次确认；运行测试并在新安装数据目录验证恢复，提交。
