# UI 精简、托管日历、提醒时间与模板库改版规格

日期：2026-10-19

## 目标

让代肝记录软件更易读、更轻、更快操作：统一字号和排版，去掉冗长常驻说明；在托管订单详情用日历查看逐日完成情况；提供易操作的提醒时间输入；模板库暂时只内置一个通用模板并保留文件导入，移除重返未来：1999与鸣潮两个专用内置模板。

## 已确认的范围

用户已确认上述四项界面改版，并补充明确：两个游戏专用内置模板可以直接删除，保留一个通用模板和导入入口，之后再设计/导入游戏模板。用户提供三张参考图：托管列表卡片采用清晰的大标题与坚持天数；详情页在简洁信息结构中展示月历，完成日期使用黄色圆点/填色；时间控件需替换现有不便使用的转盘。参考图用于理解视觉方向，不要求照搬无关字段。

## 设计

### 视觉层级与文字

沿用应用现有 Material 3 与 Compose 结构，建立一致的类型层级：页面标题约 22sp，区块/卡片标题 16sp，正文 14–15sp，辅助信息 12–13sp。按系统中文字体渲染，使用正常字重与适度行高，减少过大的标题、紧密混杂的字号和无意义粗体。数字金额、时刻和日期保持清晰可扫读。遵从系统字体缩放及触控可达要求。

交互反馈使用短而克制的过渡（约 150–220ms）：月份切换、日历完成状态变化、卡片展开等；不为纯装饰加入持续动画。保留现有主题颜色体系，以高对比状态色表达完成、进行中、逾期和危险操作。打卡完成用暖黄色强调，今天使用边框标识，两种状态可同时表达。

### 精简文字

移除页面内重复的功能介绍、常驻教学段落、重复备注提示和独立“关于功能”说明卡片。保留用户输入的订单备注、真实业务数据、字段标签、必要的空状态、操作结果、错误原因以及破坏性操作确认。重要安全语义（恢复会整体替换；未加密备份包含密码）保留但改成短句，避免用户误操作。不要删除金融数据解释中准确显示金额、期次归属或更正记录所必需的标签。

### 托管订单日历

托管订单详情显示月历，默认定位当前托管期覆盖的当前月份（当前日期不在本期时定位本期开始月份）；允许在该期日期范围内切换月份。超出所选托管期起止日的日期禁用。保留月份标题、星期标题、今天轮廓和每日视觉状态。

每个日期按该订单/期次保存的游戏时区及每日/每周刷新快照，判定当日应发生的任务。日期内所有应完成任务均完成时点亮；部分完成显示进度点；有应做任务但尚未完成则保持未完成状态；该日无应做任务或日期属于期次外时不标为完成。补录以用户选定的游戏日期计入；取消完成立即清除对应状态。选择日期显示该游戏日的任务及完成状态，可从此处进入现有补录流程。跨期续费仍按每期独立快照展示，查看往期时切换对应期次日历，绝不重写历史日期或把设备本地日期误当游戏日期。完成天数按本期至少有一个应做任务且当日所有应做任务已完成的游戏日期数统计；仅完成总量，不复刻参考图中与本业务无关的数值。

日历作为订单详情的主要进度视图；现有任务清单、补录/撤销、附件及收款功能继续可达。日历只读取现有 occurrence/period/task 数据；除通过已存在的任务完成与补录操作，不引入第二套日历数据源。

### 提醒时间输入

以现有 Material 3 时间选择器替换平台滚轮式 TimePickerDialog。采用清楚的 24 小时“小时 : 分钟”数字输入，允许键盘输入，明确“取消”和“保存”，时分范围校验后调用现有分钟值保存接口。关闭提醒类别时保留现有时间。若系统区域要求 12 小时格式，需优先保持项目当前的跨区域行为并在实现方案中明确一致的表示（用户偏好为简单直观）。

时间编辑控件仅改变设置界面选择时间的交互，不改变提醒类别、持久化、唯一工作调度、系统权限和后台送达规则。

### 模板库

首次初始化及后续启动只提供一个“通用模板”和现有 JSON 模板导入入口。移除反复未来：1999、鸣潮两个内置资源的首次播种行为，并清理已安装版本中仍留存的这两条“内置来源”记录及账号默认模板关联。清理按 Room 事务执行且可重复；保留播种标记，应用启动不会重新生成已移除模板。

清理范围仅为这两条来源仍标记为 BUILT_IN 的系统记录；用户创建或导入的同名模板、用户改写后标记为用户/导入来源的内容都保留。被清理的账号默认模板关联清空，账号和其他数据不删除。已有订单、期次、任务的来源名称、日历和任务快照完全不改。通用模板仍可编辑；JSON 导入仍按现有预览和冲突选择流程工作。

## 完成标准

- 主要页面统一视觉层级，中文布局舒适；系统字号放大后可滚动完整操作，触控目标保持可用。
- 常驻解释文字明显减少，关键数据、必要字段、错误及危险操作确认仍清楚。
- 托管日历正确展示每日、每周、所选星期、N 日一轮、补录、取消完成、无任务日期、刷新窗口、跨月和跨期状态；今天与完成可同时表达。
- 时间输入无需滚动转盘即可精确设置小时和分钟；取消不写入，保存与原设置模型一致。
- 新安装只有一个通用系统模板；既有安装的两个 BUILT_IN 专用模板被清理且账号关联归零，同名用户模板不受影响；既有订单快照、schema 历史及备份恢复契约保持正确。
- 页面和数据层有针对性的自动化覆盖；最终检查安装包与现有完整构建/迁移回归。

## 实施边界

不重新设计游戏模板内容，不改变订单/收款/打卡业务规则，不引入其他 UI 框架，不新增 schema，除非实现前调查证明现有数据层无法安全完成一键清理；如需迁移，需先把差异写回规格并供用户审阅。不修改原生通用功能之外的系统导航和颜色品牌。沿用当前 Compose、Material 3、Room 与现有 repository/viewmodel 边界。

## 设计依据

- [Material 3 typography roles](https://m3.material.io/styles/typography/applying-type)：用 display、headline、title、label、body 的职责层级组织文字。
- [Material 3 motion](https://m3.material.io/styles/motion/overview/how-it-works)：动效服务状态和交互，不持续装饰。
- [Android Compose time picker](https://developer.android.com/develop/ui/compose/components/time-pickers)：使用语义明确的小时/分钟选择，并保证可访问输入。
- [Android accessibility foundations](https://developer.android.com/design/ui/mobile/guides/foundations/accessibility)：支持系统可访问性与清晰控件标签。

## 实施前待核对项

日历点击日期后默认呈现“该日任务面板”位置和是否可单击圆日立即切换日期，不改变完成状态；实际视觉和排列在实施预览中以三张参考图为准。其余产品范围已按用户指示确定。
