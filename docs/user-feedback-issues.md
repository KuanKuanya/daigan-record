## UF-001：订单创建后无法更正服务日期

- 记录日期：2026-10-19
- 状态：已解决（v1.6，2026-10-19）
- 分类：功能缺失／订单纠错流程缺失，非使用方式问题
- 用户使用版本：未提供
- 核实范围：当前项目源码，尚未在用户安装版本上实机复现

### 用户反馈

> 我是“新增订单”的时候日期填短了，没找到能直接修改的地方，订单生成之后也没有找到删除键。错误订单一直显示在那挺奇怪的（

用户提供了托管订单详情截图，订单已到期，且已有历史打卡记录。此反馈同时涉及 UF-002。

### 修复前核实情况

- 当前订单详情没有编辑服务日期的入口，订单创建后无法直接纠正填短的期限。
- 现有“续期”会增加新的期次，保留原期次与价格，不能等同于修改原订单日期。
- 代码依据：`app/src/main/java/com/daigan/record/feature/orders/OrderDetailScreen.kt` 的 `OrderDetailContent`、`hostingSections`，以及 `app/src/main/java/com/daigan/record/data/repository/OrderRepository.kt` 的 `OrderRepository` 接口。

### 修复与验收结果

- [x] 提供清晰可发现的服务日期修改入口，支持纠正结束日期填短的情况。
- [x] 修改后，订单期限、到期状态、日历和今日任务按新日期一致更新。
- [x] 保留已有打卡、截图和收款记录；缩短日期涉及已有记录时，应明确处理规则，避免静默丢失。
- [x] 日期纠错不自动创建新期次，不误改原有价格或收款。
- [x] 自动回归验证已到期订单延长后保留打卡及价格、跨期重叠拒绝，以及短期单截止日期修改和清除；日期更新不写收款或附件表。

v1.6 实现：在订单详情右上角“管理 → 修改日期”操作。托管单可选期次，短期单可修改或清除截止日期；已有发生记录的期次锁定开始日期，结束日期不能排除已有记录，不允许期次重叠或先后顺序颠倒。价格、收款和附件不被改写。

## UF-002：误建订单无法单独删除或作废

- 记录日期：2026-10-19
- 状态：已解决（v1.6，2026-10-19）
- 分类：功能缺失／误建订单清理流程缺失，非使用方式问题
- 来源：同 UF-001 的用户反馈
- 核实范围：当前项目源码，尚未在用户安装版本上实机复现

### 修复前核实情况

- 当前订单详情未提供单独删除、取消或作废订单的入口，订单仓储接口也没有相应操作。
- 现有截图删除、收款作废等操作不属于订单删除或订单作废。
- 影响：用户无法自行清理误建订单，错误订单持续展示。
- 代码依据：`app/src/main/java/com/daigan/record/feature/orders/OrderDetailScreen.kt` 和 `app/src/main/java/com/daigan/record/data/repository/OrderRepository.kt`。

### 修复与验收结果

- [x] 提供单个误建订单的清理入口和明确的操作确认。
- [x] 区分无业务记录的误建订单与已有打卡、附件或收款的订单，确定删除或作废规则。
- [x] 明确处理后的列表展示、今日任务、老板置顶、待收款和统计口径，避免错误订单继续影响正常使用。
- [x] 已有收款和历史业务记录不得未经说明直接丢失。
- [x] 自动回归验证空单删除、已有打卡/收款拒绝删除、作废后保留收入并移除待收与任务；后端同时保护附件、批量操作引用和续期记录，禁止直接删除。

v1.6 实现：在右上角“管理”中操作。无业务记录的误建订单确认后删除；已有记录只能作废。作废保留历史与实际收款，取消剩余待收、任务、提醒和有效接单计数；已有收款可继续更正或作废。删除与作废均不可撤销，确认框明确提示。

## UF-003：归档游戏账号持续展开显示，缺少收起或隐藏方式

- 记录日期：2026-10-19
- 状态：已解决（v1.6，2026-10-19）
- 分类：归档展示体验问题，非使用方式问题
- 用户使用版本：未提供
- 核实范围：当前项目源码，尚未实机复现

### 用户反馈

> 选择“归档游戏账号”后能不能出一个收起折叠/隐藏或者删除的功能，一直显示在下面也挺奇怪的（

### 修复前核实情况

- 老板详情将已归档账号列在正常账号下方，显示“已归档账号”标题并直接展开全部条目，没有折叠入口。
- 软件另有独立的“归档记录”页面，可查看归档账号；老板详情仍会展示这些账号。
- 代码依据：`app/src/main/java/com/daigan/record/feature/accounts/OwnerDetailScreen.kt` 的已归档账号列表，以及同目录的 `ArchivedRecordsScreen.kt`。

### 修复与验收结果

- [x] 为老板详情中的已归档账号提供折叠或隐藏方式，减少长期占用列表空间。
- [x] 隐藏或收起后仍能找到查看及恢复入口，不影响正常账号列表。
- [x] 默认收起，并按老板 ID 保存展开状态，切换其他老板时重置；状态恢复与恢复账号回调均有界面测试。
- [x] 本版本采用折叠方式，保留查看和恢复；不增加账号永久删除操作。

v1.6 已采用用户确认实施方案中的默认折叠方式。

## UF-004：重复周期支持每月固定几号更新

- 记录日期：2026-10-19
- 状态：已解决（v1.6，2026-10-19）
- 分类：新增功能需求，非现有功能 bug
- 用户使用版本：未提供
- 核实范围：当前项目源码

### 用户反馈

> “重复周期”里能加一个指定日期更新

用户后续确认：指每个月固定几号更新，即按月重复，不是指定某个年月日的一次性任务。

### 修复前核实情况

- 当前周期模型包括一次性、每日、每周、指定星期和每隔若干天。
- 托管建单的“重复周期”选项排除了一次性，未提供指定日历日期的选项。
- 代码依据：`app/src/main/java/com/daigan/record/data/model/Order.kt` 的 `RecurrenceType` 和 `app/src/main/java/com/daigan/record/feature/orders/NewOrderScreen.kt` 的重复周期设置。

### 修复与验收结果

- [x] 确认周期含义：每个月固定几号更新。
- [x] 在重复周期中增加按月选项，支持设置月内固定日号。
- [x] 日号范围为 1–31；当月不存在该日时跳过当月，不改到月底执行。
- [x] 按游戏时区及每日刷新后的游戏日判断日号，服务期限外不生成任务；接入日历、补录、提醒、模板及备份。
- [x] 验证大小月、二月、闰年、跨年及订单期限边界的行为，确保不会重复或提前生成任务。
- [x] 验证已有每日、每周、指定星期及每隔若干天任务的行为不受影响。
